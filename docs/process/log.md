## Этап 0. Анализ и дизайн (до кода)

**Задача ИИ.** «Изучи проект, проанализируй задачу, создай план, но не начинай создавать проект сразу. Создай дизайн-артефакт с 6 дизайнами».

**Как шли раунды** (холст: страницы r1–r9):
1. **6 концепций** (Сегодня, Ночной кампус, Сетка, Спроси деканат, Карта семестра, Квест) — отклонены: «скучно и обычно».
2. **Раунд 2: ИИ как новый способ говорить с деканатом** (Командная строка, Газета дня) — жёстко отклонены: «как DOS», «форум 2000-х».
3. **Раунд 3** по референсам (Стекло, Плейлист) — отклонены: случайные градиенты, копия Dynamic Island и Яндекс Музыки. *Ошибка ИИ:* сгенерировал «похожее на известное» вместо своего. *Как поймали:* пользователь указал на плагиат. *Вывод:* референсы — для принципов, не для формы.
4. **6 вариантов «расписание в центре»** → пользователь назвал номера, понравившиеся элементы.
5. **Раунд 6** — доработка R1–R3 и новые N4–N6 + экраны документов и ИИ. Подключили **субагента-дизайнера** для объективной оценки по критериям.
6. **Разгрузка** («не перегружен ли интерфейс?») — одна точка фокуса, «По делам» вместо трёх блоков.
7. **R2 «Карточки» v5 — финал**: главная ПК и телефон, насыщенный день (6 пар), неделя, заявки (нет точной даты, нужно действие), учёба, вход, профиль, уведомления, загрузка/офлайн/выходной, ошибки и фокус.

**Ошибки ИИ на этапе дизайна и как их нашли**
- Шаблонная подстановка цвета `{{hero}}` не работала внутри CSS — телефоны на холсте стали серыми. Локальное превью это маскировало. *Поймал пользователь*; исправили через CSS-переменную на корне. *Вывод:* проверять в той же среде, где смотрит человек.
- Ответы и план задач были на английском — пользователь не понял, что ПК-версию переделали, и попросил откатить. *Вывод:* всё общение и интерфейс — по-русски (правило в памяти агента).
- Пустые места внизу экранов заявки — заполнили полезным («Что в заявке», «Может понадобиться ещё», «Документы в заявке»).

## Этап 1. Архитектура (22 ноября)

**Промпт пользователя.** «Начинай реализацию. Только давай не торопиться. Разобьём на фазы… начать с планировки архитектуры. Она должна быть правильная с самого начала. Сходство с дизайном — максимальное. Изобилие красивых и качественных анимаций».

**Что сделали.** `docs/architecture.md`: требования ТЗ → решения; стек; модель данных; два слоя защиты; масштабирование; система движения (токены + каталог анимаций по экранам); ИИ-помощник с запасным режимом; 10 фаз с определением «готово».

**Решения пользователя.** Реалии ДВФУ; ключ GigaChat получит сам; хостинг — открыт (вопрос про GitHub Pages → ADR 0001).

## Фаза 1. Фундамент

**Что сделали**
- Проект Next.js 16 + TS strict; версии пакетов выбраны скриптом «последняя версия старше 14 дней» (защита от атак через свежие пакеты).
- Схема БД (24 таблицы), миграция безопасности с RLS, роль `app_user` без особых прав.
- Сид в реалиях ДВФУ: 2 студента разных институтов + методист, 474 занятия на семестр, переносы на текущей неделе.
- 16 тестов безопасности базы — зелёные.
- `CLAUDE.md`, 4 агента, `docs/security.md`, ADR.

**Ошибки и препятствия**
| Что случилось | Как нашли | Что сделали |
|---|---|---|
| npm упал с `Cannot read properties of null (edgesOut)` | вывод установки | Известный баг npm с peer-зависимостями → `legacy-peer-deps` в `.npmrc`, недостающий `vite` поставлен явно |
| `eslint-config-next` несовместим с ESLint 10 | лог ERESOLVE | ESLint 9 |
| TypeScript 7 (нативный) — риск несовместимости с Next | проверка версий | TypeScript 6.0.3 |
| Колонка `issued_at` создавалась как `created_at` (общий хелпер) | миграция упала на функции проверки справки | исправили схему, пересоздали миграции — **функция-проверка поймала ошибку схемы** |
| Docker Desktop не поднялся | `docker info` | отдельный Postgres 18 в папке проекта (`.pgdata`, порт 54329), системный не тронут |
| `next/font/google` не скачал шрифт | сборка упала | шрифт в проекте (ADR 0004) — заодно убрали зависимость от Google для жюри |
| `const enum` из argon2 при `isolatedModules` | `tsc` | числовое значение с комментарием |

## Фаза 2. Дизайн-система и анимационный кит

**Промпт пользователя.** «Да, фаза 2».

**Что сделали**
- Токены цветов, теней, радиусов перенесены из CSS макетов в `src/styles/tokens.css` и тему Tailwind.
- 31 иконка — те же контуры, что в макетах (выгружены скриптом из всех `.dc.html`).
- Кит движения `src/components/motion`: токены пружин, каскад, «перекат» цифр, счёт вверх, скользящая подложка, рисуемая линия, вспышка изменений, покачивание ошибки, скелетоны, тосты (смахиваются), строка «смахни — прочитано», кнопка «текст → индикатор → галочка». Всё уважает «уменьшить движение».
- Примитивы и каркас: кнопки, строки, плашки, верх и таб-бар телефона, шапка и полоса дней ПК, блоки главной.
- Витрина `/dev/kit` и две страницы сверки: `/dev/kit/phone` (390×844) и `/dev/kit/desk` (1086×844).

**Сверка с макетами.** Макет и реализация снимались в одном браузере в одном размере, затем сравнивались рядом. Совпадение — до пикселей; макет в превью рисуется запасным шрифтом (Google Fonts недоступен), реализация — настоящим Inter Tight.

**Ошибки и как нашли**
| Что случилось | Как нашли | Что сделали |
|---|---|---|
| Текст на чёрной кнопке не виден, «Войти» потеряла жирность | скриншот рядом с макетом | базовые стили `button { color: inherit }` были вне слоя Tailwind и перебивали утилиты → перенесли в `@layer base` |
| В крупном «10» цифра «1» занимала ширину «0» | сравнение с макетом | колонка «перекатываемых» цифр брала ширину самой широкой цифры → ширину задаёт невидимая текущая цифра |
| На 360×780 «По делам» заезжала под таб-бар | проверка на узком экране | страница прокручивается, таб-бар прилипает к низу |
| Счётчик дней в демо не подсвечивал активную вкладку | скриншот | адрес демо не `/` → параметр `activeHref` для демо и тестов |
| Длинная heredoc-вставка в оболочке не разобралась | ошибка bash | файлы записаны по одному инструментом записи |
