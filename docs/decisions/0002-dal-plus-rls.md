# 0002. Два слоя защиты: DAL + Row-Level Security

**Решение.** Все запросы — через слой `src/server/dal` с владельцем из сессии; плюс политики RLS в Postgres под ролью `app_user` без обхода RLS.

**Почему.** Самая частая уязвимость таких кабинетов — IDOR (забыли проверить владельца). Код пишут ИИ-агенты, и одна пропущенная проверка — утечка. RLS делает ошибку «закрытой»: без контекста видно пустоту.

**Цена.** Каждый запрос в транзакции с `set_config`; аккуратность с ролями при сиде (сид работает от владельца схемы).
