# деканат* – правила проекта для ИИ-агентов

Концепт личного кабинета студента для конкурса «Цифровой деканат будущего». Не официальный сервис вуза. Все данные вымышленные. Реалии – ДВФУ (Владивосток, кампус на о. Русский).

**Прежде чем менять код, прочитай `docs/architecture.md`.** Если задача расходится с документом, сначала обнови документ (и при необходимости добавь ADR в `docs/decisions/`), потом код.

## Стек
Next.js 16 (App Router), React 19, TypeScript strict, Tailwind 4, Motion, Radix UI, dnd-kit, Drizzle ORM + PostgreSQL 18 (RLS), argon2id, zod, Vitest, Playwright. Версии зафиксированы точно. Новые пакеты – только версии старше 14 дней, с точной версией.

## Железные правила безопасности
1. **Доступ к БД – только через `src/server/dal/*` и `src/server/services/*`** и только через `withDb(ctx, …)`. ESLint запрещает импорт `@/server/db` и `drizzle-orm` из остального кода.
2. **`studentId`/`userId` берётся только из сессии** (`requireStudent()` / `requireStaff()`), никогда из URL, формы, тела запроса или ответа ИИ.
3. **Чужое = 404**, не 403. Запрос по id всегда с условием владельца, даже если RLS это и так отрежет.
4. Каждый Server Action и Route Handler сам проверяет сессию и валидирует вход через zod.
5. В клиентские компоненты уходят только DTO с нужными полями. Никаких `password_hash`, токенов, внутренних ключей.
6. Секреты – только `process.env` на сервере. Никаких `NEXT_PUBLIC_` для секретов. Ключ GigaChat читается только в `src/server/ai`.
7. Новая таблица с личными данными → политика RLS в новой миграции + тест в `tests/security/`.
8. **Не ставить `loading.tsx` над страницами с параметром из адреса (`[id]`, `[courseId]`).** Потоковая отдача отправляет статус 200 раньше, чем сработает `notFound()`, и чужой объект перестаёт отвечать 404. Экран загрузки – только у страниц без параметров (`(home)`, `week`).
9. Только вымышленные данные. Никаких реальных ФИО, номеров зачёток, логотипа вуза. Дисклеймер `UNIVERSITY.disclaimer` должен быть виден на входе и в профиле.

## Дизайн: максимальное сходство с макетами
- Эталон – `design/boards/*.dc.html` (тексты всех макетов – `design/texts.txt`). Перед вёрсткой экрана открой его макет и повтори размеры, отступы, тексты.
- Цвета, радиусы, шрифт – только токены из `src/styles/tokens.css` (классы Tailwind `bg-hero`, `text-ink-2`…). Hex-коды в компонентах запрещены.
- Телефон (< 1024 px) – язык B2Phone: оранжевый верх, тёплые нейтральные, таб-бар с иконками. Компьютер (≥ 1024 px) – язык B2Next: серый фон, белые карточки, чёрные активные элементы.
- Правила макета: ≤ 3 оранжевых акцентов на «простыне», одна чёрная главная кнопка на экран, статус – словами, зона касания ≥ 44 px.
- Проверка 360 px обязательна: никакой горизонтальной прокрутки.

## Анимации
- Только из кита `src/components/motion` (токены в `motion/tokens.ts`). Новая анимация → сначала компонент в ките, потом использование.
- Анимируем `transform`/`opacity`/`filter`/`clip-path`, раскладку – через `layout` (FLIP).
- Каждая анимация отвечает на вопрос «что произошло?». Вход экрана ≤ 600 мс, ввод не блокируется.
- `prefers-reduced-motion` → мягкое появление вместо движения, счётчики сразу показывают итог.

## Определение «готово» для экрана
1. Экран совпадает с макетом на 390×844 и 1086×844 (снимок рядом с макетом в отчёте сверки) и не ломается на 360 px.
2. Есть состояния: загрузка (скелетон), пусто, ошибка.
3. Работает с клавиатуры, видимый фокус, подписи для экранных дикторов.
4. `npm run check` зелёный, сценарий Playwright есть.
5. Запись в `docs/process/log.md`: что сделали, ключевой промпт, ошибки ИИ и как их нашли.
