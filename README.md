# деканат* – концепт личного кабинета студента

Работа на конкурс «Цифровой деканат будущего». **Не официальный сервис вуза. Все данные вымышлены.** Кабинет адаптирован под реалии ДВФУ (время Владивостока, корпуса кампуса, сетка пар), логотипа вуза нет.

Всё об учёбе в одном месте: расписание с переносами и живым отсчётом до пары, баллы и допуск с калькулятором, справки онлайн со статусом и PDF с QR, уведомления в реальном времени, ИИ-помощник, который сам собирает заявку по фразе, и кабинет методиста, который эти заявки обрабатывает.

**Прототип:** https://62-84-113-209.sslip.io (сервер в России, Yandex Cloud, открывается без VPN, работает до объявления итогов 28 ноября).
**Описание процесса:** [docs/report/deanery-process.pdf](docs/report/deanery-process.pdf).

## Что внутри

| Раздел | Что умеет |
|---|---|
| Сегодня | Отсчёт до следующей пары, расписание дня с заменами и переносами, «Войти» у онлайн-пары, по нажатию на пару – окно с аудиторией, схемой этажа и материалами, «По делам». Насыщенный день, вечер и выходной – свои экраны. На компьютере – полоса дней и настраиваемые блоки |
| Неделя | Все пары по дням (телефон) и сетка по парам (компьютер), панель «На этой неделе», выгрузка в календарь (.ics) |
| Учёба | Средний балл, допуск к экзаменам, предметы с баллами, «что сделать для допуска», калькулятор «сколько нужно на экзамене», зачётная книжка |
| Документы | Заказ справки за минуту, статус и честный срок («точной даты пока нет – по правилам до…»), загрузка документов, готовая справка в PDF с QR и публичной проверкой |
| Уведомления | Лента с фильтрами, всплывают сразу (SSE), проактивные напоминания о сроках |
| Помощник | «Нужна справка в военкомат» → собранная заявка с источником каждого поля; ответы про пары, баллы, заявки. GigaChat + запасной режим на правилах |
| Профиль | ФИО, институт, направление, курс, группа; студенческий с QR; цвет главной; демо-время; выход на всех устройствах |
| Кабинет сотрудника | Очередь заявок, смена статусов (студент видит сразу), перенос пар и замена аудиторий, объявления |

Аккаунты тестовые, все данные в них выдуманы, поэтому пароли открыты. Заданы в `.env.example` (`SEED_PASSWORD_*`); в базе хранятся только их отпечатки argon2id.

Главную на компьютере можно собрать под себя: блоки перетаскиваются за ⋮⋮ в шапке, а через «···» открывается настройка – размер S / M / L, скрытие блоков и готовые раскладки. Нажатие на любую пару открывает окно с подробностями: аудитория и схема этажа, преподаватель, изменения, материалы.

Если открываете кабинет вечером или в выходной, в профиле можно включить «Демо-время»: кабинет покажет учебный день с живым отсчётом до пары. Чтобы увидеть реальное время в работе – откройте студентку и методиста в двух окнах: студентка заказывает справку, методист берёт её в работу и отмечает «Готова», у студентки статус и уведомление появляются сразу.

## Как устроено

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind 4 · Motion · PostgreSQL 18 (Row-Level Security) · Drizzle ORM · argon2id · Docker + Caddy. Подробно – [docs/architecture.md](docs/architecture.md).

**Безопасность** ([docs/security.md](docs/security.md)):
- Пароли – argon2id; в cookie – случайный ключ сессии, в БД – только его хеш.
- Чужие данные закрыты дважды: код всегда спрашивает «эту заявку *этого* студента», а сама база (RLS) проверяет каждую строку. Чужая заявка, файл, PDF или предмет по прямой ссылке – 404.
- Ключ GigaChat – только в переменных окружения сервера; браузер его не видит.
- CSP с одноразовым nonce, лимит попыток входа, проверка Origin, проверка типа файлов по сигнатуре.

## Запуск

```bash
cp .env.example .env            # заполнить пароли БД
npm ci
docker compose -f compose.dev.yaml up -d --wait   # или свой Postgres 18
npm run db:migrate && npm run db:seed
npm run dev                     # http://localhost:3000
```

Продакшен на одном сервере: `docker compose up -d` (база, миграции, приложение, Caddy с HTTPS); переменные – в `.env` рядом (`DOMAIN`, `DB_OWNER_PASSWORD`, `APP_DB_PASSWORD`, `GIGACHAT_AUTH_KEY`, `SEED_PASSWORD_*`, `RUN_SEED=1` при первом запуске).

## Проверки

```bash
npm run check        # линтер, типы, тесты базы и логики (Vitest)
npm run test:e2e     # сценарии в браузере на 360 px и на компьютере (Playwright)
```

Тесты безопасности: RLS напрямую в БД, матрица IDOR (чужие заявки, файлы, PDF, предметы), CSRF, перебор пароля, подделанная и старая cookie, секреты в бандле.
